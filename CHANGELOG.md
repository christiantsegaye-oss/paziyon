# Changelog

A running log of the build, newest entry first. Prefixes: `feat` / `fix` / `docs` / `chore`. Each entry says what changed and why.

## 2026-10-09: Voxide voice and a loud siren

- `feat`: **Voxide is now the voice** in the app and the web demo. It listens for "help" and "I'm okay" and for bystanders' questions in Amharic, Afaan Oromo and English. It speaks the countdown, the first-aid steps and its answers in a natural voice, replacing the robotic espeak clips. It acts through six app capabilities: start or cancel the alert, alert status, first-aid step, medical ID, and call 907. The Android app runs Voxide in a hidden WebView served from localhost. Add the team's `vox_pub_` key in Settings, or as the `VOXIDE_KEY` repository variable for CI builds (see `docs/VOXIDE_SETUP.md`). With no key or no internet, the phone recognizer and the clips still work.
- `feat`: **loud siren during an alert.** It plays for 6 s before the first step and for 3 s between steps. On Android it uses the alarm channel at full volume, so it sounds even in silent mode, and the previous volume is restored afterwards. It pauses when a bystander speaks. Bystanders can tap **Silence siren**, and it can be turned off in Settings. The sound is generated by `tools/generate_siren.py`.
- `test`: 64 Flutter tests, adding Voxide flows with a fake agent and the siren. 35 web tests, adding the shared engine against a fake SDK and a check that the web demo and app ship identical Voxide files.

## 2026-10-01: P.A.Z.I.Y.O.N, help with the phone locked, Amharic/Oromo audio

- `feat`: renamed to **P.A.Z.I.Y.O.N** with the team's logo. `tools/make_icons.py` cuts the artwork out of the 3D render and builds every launcher size, an adaptive icon that keeps the art inside the launcher-safe zone, the in-app logo and the web favicon.
- `feat`: **help with the phone locked or the screen off.** Pressing the power button 3 times within 3 seconds starts the alert from the background service. A local plugin (`app/packages/power_trigger`) streams screen on/off changes, since apps cannot read the power button directly. The lock-screen notification also gets a **Get help now** button.
- `feat`: **Amharic and Afaan Oromo spoken output.** Phones have no voice for either language, so the first-aid steps, countdown and answers were silent. 136 clips are now bundled (generated offline with espeak-ng by `tools/generate_audio.mjs`) and play in the app, the background service and the web demo. The voice is robotic; replace any clip with a human recording of the same file name.
- `fix`: the app no longer decides from the phone's language list that Amharic is unsupported (the list is often incomplete). It tries the language, and falls back to English if the phone reports it can't do it, or hears speech it can't match three times in a row.
- `fix`: an interrupted clip never signalled that it had finished, which would leave the echo filter treating the phone as still speaking.

## 2026-09-27: Voice fix and FirstVoice redesign

- `fix`: the voice command was heard but never acted on. Android often ends a recognition session without sending a "final" result, and the app only acted on final results. It now acts on the first partial result that matches, once per utterance, so "help" works the moment it's said and a bystander's question is answered once.
- `fix`: when the phone or browser can't recognize the chosen language (common for Amharic on phones and for Afaan Oromo in Chrome), voice used to hear nothing, silently. It now falls back to English and shows why on screen, next to a live "hearing…" line.
- `fix`: the echo filter remembered everything the phone had said, so after an alert (the phone says "Please help them") a real "help" was ignored. It now only ignores speech that is still playing or ended in the last 4 seconds. Found by a new browser test with a simulated recognizer.
- `fix`: phrases match whole words ("help" alone triggers, "helpful" doesn't). Added ድረሱልኝ, stop, false alarm and I'm alright.
- `feat`: redesigned as **FirstVoice** in both the app and the web demo. Design tokens (zinc neutrals, one emergency red, green only for safe, amber only for attention), bundled Outfit and Noto Sans Ethiopic fonts, icons instead of emoji, grouped settings rows, a ring countdown and a calmer bystander screen. The web demo also gets the mobile-native baseline: `dvh`, safe areas, no tap flash, `:active` press feedback, hover only on devices that can hover, 16px inputs.

## 2026-09-25: Day 0 (idea submission)

- `feat`: background protection. A foreground service keeps fall detection running with the app closed or the screen off. If nobody is at the phone, it runs the countdown in a full-screen notification with an "I'm okay" button, sends the alert SMS itself, and speaks the first-aid steps. When the app is on screen, the service hands the fall to the app so voice cancel works. When the app is opened mid-alert, it takes over with the original timing and nothing is sent twice. The rules live in `BackgroundCoordinator` with 8 unit tests, plus 3 widget tests for the handoff.
- `fix`: the first CI APK build failed. The direct-SMS plugin's Kotlin JVM target (1.8) didn't match its Java target (11), and `flutter_local_notifications` needs core-library desugaring. Fixed both, and removed the unused `permission_handler`, which wanted Android SDK 37.

- `feat`: Flutter Android app in `app/`. It ports the prototype's logic one-to-one and adds what a browser can't do: the alert SMS goes out directly from the phone (works offline) and an "I'm okay" SMS follows when the alert is resolved. Fall detection reads the real accelerometer. Voice uses Android's recognizer behind one `VoiceInput` interface until Voxide lands.
- `test`: 30 Flutter tests. The 26 core unit tests mirror the JS suite and include decoding a link made by the web prototype. Four widget tests drive the whole app through fake phone services: voice trigger with echo ignored and voice cancel; hold to alert, SMS, bystander Q&A in English and Amharic, call 907, hold to stop; a simulated fall; data surviving a restart.
- `fix`: found by those tests. The hold-to-stop button touched its animation after the screen had closed, the bystander timer and language buttons overflowed on a narrow phone, and the listening-language picker overflowed its card.
- `chore`: CI runs the prototype and app tests and builds `app-release.apk` on every push.

- `feat`: browser prototype of the full flow in `prototype/`. It covers the voice trigger and voice cancel in three languages, a hold-to-alert button, a countdown with a cancel window, rule-based fall detection with a simulator, and bystander mode with looping first-aid steps. Bystanders can ask questions by voice and get answers in the language they asked in. An SMS with a GPS link opens the caregiver dashboard. Built to demo the concept before the Flutter app exists and to pin down the logic the app will port.
- `feat`: core logic as pure, unit-tested modules (24 tests): the alert state machine, fall detector thresholds per sensitivity, voice intent routing, and the SMS format. They serve as the reference for the Flutter port.
- `fix`: ignore the phone's own voice picked up by the microphone. Without this, the countdown prompt "Tap cancel if you are okay" cancelled itself, and the first-aid step "call emergency services" matched the call-for-help intent.
- `fix`: allow 500 ms for the phone to settle after impact before checking stillness. A 300 ms window treated the post-impact bounce as movement and missed real falls.

- `docs`: add the concept README with the voice-first submission wording, core flow, planned stack, team roles and milestones. The idea is now locked with voice as the headline feature, as STARK requires.
- `docs`: add the full technical spec (`docs/SPEC.md`, converted from the original `.docx`) so the whole team works from one versioned source.
- `docs`: start the decisions log (`docs/DECISIONS.md`) with the routes rejected so far: seizure detection on the phone, a wearable companion, data-only alerting, and audio-only "voice". It feeds the Scholarxiv ideation trail.
